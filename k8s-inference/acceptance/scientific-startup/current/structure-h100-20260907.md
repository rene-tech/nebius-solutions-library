# Current structure-model startup: H100, 2026-09-07

All five profiles passed three fresh-process repetitions with their unchanged
deployed model image, full inference arguments and accepted input artifacts.
The [machine-readable report](structure-h100-20260907.json) includes every
timestamp, monotonic duration, image/input/output digest and distribution.

These are **existing-cache startup measurements**, not disk-cold starts or GPU
snapshot restores. Model/reference files and container images were already
available on the existing reserved H100 pool. No cache eviction, GPU tuning,
precision/step reduction, production deployment or capacity change occurred.

**Initialized does not mean fully shape-warmed.** ESMFold2/Fast, Protenix and
OpenFold3 markers synchronize CUDA at their post-initialization boundary.
AlphaFold3's native loader returns **host** parameters; JAX device placement and
compilation remain first-inference work. Its 8.09s number must not be presented
as GPU-ready startup. First compute, including any lazy compilation and normal
inference, took median 5.07s / 4.50s / 9.50s / 14.26s / 8.61s respectively. This
does not independently isolate compilation from compute.

Validated full output means the original complete model command exited zero,
then finite atom coordinates and non-empty complete structures were verified.
This is the first **verified full output**, not the earliest file write, public
artifact delivery, or an arbitrary Pod Ready condition. Small fixed acceptance
inputs make the measurements reproducible; output time is not a prediction for
longer proteins, larger complexes, additional seeds or MSA searches.

## Reproduction and limitations

`structure_public_runs.py` first reuses the existing public acceptance runner
to establish a normal valid request/result for every profile. An additional
AlphaFold3 public run refreshed its short-lived template. These six controls
are not counted among the 15 instrumented repetitions.

`structure_isolated_runs.py` clones the accepted GPU stage into task-owned
Kueue Jobs, retaining the original resources, scheduling pool, model/reference
mounts, argv and model images. It mounts benchmark-only explicit function hooks
and a supervisor. Authorized public input downloads are checked against their
frozen digests, then passed through the unchanged materialization validator.
Expired workload capabilities are not reused. The original artifact collector
is omitted so the probes cannot publish into completed source operations.
Consequently **public-request-to-ready is not measured by this overlay**; Pod
timings include local input initialization, not the original full CPU-stage
workflow. At most three structure-model GPU jobs ran concurrently.

Example, from `k8s-inference`, using private paths and a previously captured
accepted Job list:

```sh
python acceptance/scientific-startup/current/structure_isolated_runs.py \
  --jobs-file "$BENCHMARK_PRIVATE_DIR/accepted-jobs.json" \
  --model esmfold2 --repetitions 3 \
  --outputs "$DEPLOYMENT_PRIVATE_DIR/final-stack-output.json" \
  --kubeconfig "$DEPLOYMENT_PRIVATE_DIR/kubeconfig" \
  --repository-root "$INFERENCE_SOURCE_DIR" \
  --receipts "$BENCHMARK_PRIVATE_DIR/esmfold2-isolated" --suffix fresh
python acceptance/scientific-startup/current/structure_hook_tests.py
python acceptance/scientific-startup/current/structure_report.py \
  --private-root "$BENCHMARK_PRIVATE_DIR" --output structure-report.json
```

The report generator requires exactly three successful physical receipts per
profile and rejects negative or missing clocks. It strips endpoint, capability,
operation, artifact-handle, node and filename identities from the public report.
Raw private receipts/logs remain checksum-linked for operator reproduction.
