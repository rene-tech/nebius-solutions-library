# Primary scientific startup — H100, 7 September 2026

All five assigned profiles passed three real fresh-process starts and produced
valid outputs with their current images, weights, runtime settings and resource
envelopes. BoltzGen has its own detailed report; the other four are detailed in
the accompanying [machine-readable evidence](primary-h100-20260907.json).

These are **current cached-node starts**. Images were already present and the
immutable model/reference-data mounts stayed localized. They are not disk-cold
downloads, new-node starts, GPU snapshot restores or fully shape-warmed first
inferences. No image, weights, precision, workload size, limit, quota, driver,
GPU mode, production policy or production service was changed.

## Boundaries and validation

- Proteina-Complexa uses upstream's timestamped `cfg_gen` boundary after its
  checkpoint/model setup and immediately before generation. All three complete
  public four-stage operations passed semantic validation with the same
  execution identity. Two earlier public successes are retained as output
  controls but excluded because the observer did not retain their internal
  `cfg_gen` file.
- RFdiffusion uses upstream's timestamped `Making design` line, emitted after
  checkpoint load and sampler construction. All three complete public workflows
  passed semantic validation and released every stage resource.
- Mosaic uses `simplex_APGM` entry after Boltz2 and ProteinMPNN checkpoint
  loading, feature/loss construction and initial JAX dispatch. Each unchanged
  run produced a 200-atom finite structure, finite metrics and a 40-residue
  sequence.
- BindCraft uses the first `mk_afdesign_model` return after PyRosetta setup and
  AlphaFold parameter loading. Each unchanged full design run produced a finite
  1,117–1,122-atom structure and finite model-specific metrics. Its lazy
  ProteinMPNN model became initialized later, median **212.70 s** after container
  start; that includes preceding design work and is not called startup.
- BoltzGen uses the post-restore prediction-loop boundary after native device
  placement and CUDA synchronization. `LOCAL_RANK` and generic weight-load
  messages are deliberately not readiness. See
  [the BoltzGen report](boltz-h100-20260907.md).

Mosaic and BindCraft use JAX. `jax.effects_barrier()` does not prove
`block_until_ready()` for every pure parameter array, so their numbers are
native initialization/post-loader boundaries—not synchronized, shape-warmed
GPU-ready promises. Lazy compilation and first compute remain downstream.

Validated output means the public semantic validator passed, or, for isolated
Jobs, the unchanged command exited zero and the independent supervisor verified
finite structural coordinates, required finite metrics and a non-empty protein
sequence. Full-output time is intentionally separate from initialization.

## Method and reproducibility

`primary_run.py` submits fixed accepted inputs through the public scientific API
and captures timestamped Pod, Event and native-log evidence. The Proteina log
follower is independent of the outer container follower so the internal source
timestamp cannot be skipped after a Pod transitions to Running.

For runtimes without a reliable public post-load marker,
`primary_isolated_runs.py` clones a successful admitted GPU Job while preserving
the digest-pinned runtime image, model mounts, argv, precision, work size,
resources and scheduling. It removes only the output uploader, fetches the
original input through the authorized API, verifies its frozen size and digest,
and passes the same bytes through the unchanged materializer into a fresh
workspace. Benchmark-only import hooks emit the boundary; `primary_supervise.py`
runs the original argv and independently verifies its output. Expired workload
capabilities are never reused.

BindCraft harness attempts `a`–`d` failed before a valid model-ready boundary
because of benchmark setup defects (missing init capture, UUID path conversion,
Python 3.10 `datetime` compatibility, and canonical PyRosetta `PYTHONPATH`
ordering). They are excluded and retained with log hashes. The corrected `e`,
`f` and `g` trials all passed without relaxing runtime gates or semantic checks.

Measurements ran on the two retained capacity-block H100 nodes in
`project-e00rene`, `eu-north1`. Separately allocated GPUs overlapped with other
authorized probes on shared hosts, so these are not dedicated-node maximum
performance claims. Kubernetes lifecycle timestamps have one-second resolution;
extra decimals retain source calculations, not sub-millisecond infrastructure
accuracy.

Raw receipts and logs remain under the private evidence root
`/home/tux/.local/state/fs2-startup-benchmark-r20260907/primary`; hashes and
individual clocks are in the JSON. Raw Job specs remain private because they can
contain short-lived workload handles. All task-owned Jobs, Pods and ConfigMaps
were removed, while production Qwen and the cluster remained running.
