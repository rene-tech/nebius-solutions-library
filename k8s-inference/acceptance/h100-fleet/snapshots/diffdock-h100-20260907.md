# DiffDock: optional H100 GPU snapshot qualification

Three matched normal/restore pairs passed on 7 September 2026. Every fresh
worker ran the unchanged digest-pinned upstream DiffDock server and both
original accepted requests: the pinned RCSB 1UBQ receptor with aspirin at
seeds 2370 and 2371. The strict native validator checked the receptor identity,
ligand identity, generated SDF coordinates and finite confidence values. The
donor Pod was deleted before restore testing, so this is a real CUDA + CRIU
restore and not reuse of a retained GPU process.

| Clock, median (range), 3 runs each | Normal loading | Snapshot restore |
| --- | ---: | ---: |
| Container start → observed model-ready | 24.514s (24.097–25.557) | 8.890s (8.836–10.287) |
| Pod-create request → observed model-ready | 29.008s (28.830–29.373) | 14.276s (14.211–14.408) |
| Container start → both validated outputs | 52.320s (52.062–53.224) | 30.692s (30.516–32.248) |

The ready boundary is the application HTTP health endpoint after the snapshot
supervisor completed CUDA + CRIU restoration. Normal trials use the original
server health endpoint. Snapshot restore improves the matched median
container-to-ready clock by 15.624 seconds (63.7%). Request-specific work can
still happen after readiness. The full-output clock includes two sequential
requests, client transport and validation, so it is not a pure inference or
first-output benchmark.

These measurements retain the current regional image, localized-weight and
shared-filesystem caches. They do not measure disk-cold startup, node
acquisition, an image pull, reserved host RAM or another GPU family. Normal
loading remains the production default until this exact bundle is registered,
selected and passes a live fallback rollout.

## Immutable evidence

The [qualification JSON](diffdock-h100-20260907.json) contains all six
fresh-Pod trials, exact request and response hashes, semantic invariants,
runtime compatibility and private raw-receipt hashes. The published snapshot
bundle is 5,881,987,787 bytes across 236 entries. Its canonical
content-and-filesystem-metadata manifest SHA-256 is
`3d6a2da41134cfb25355a5ddffd3ac84b74f6ebe8d4206901c54905ca354648b`.

- Runtime image: `diffdock@sha256:471db264f4c544e1798c090f13b6cf94b3fbd304fb2c91e9f63a3dd33c9d81d7`.
- Model revision: `85c49b60d3e0b0182a59ee43a34a6d7036981284`.
- Artifact manifest: `sha256:75368bdd1d6126faa99bb716aac4409215f2217fb827750aed117b273bee889b`.
- H100 80 GB, SM90, driver `580.159.04`, kernel `6.11.0-1016-nvidia`.
- Capture components: CUDA checkpoint 1.871s, CRIU dump 69.792s, durable
  flush 0.648s.

The original fixture was deliberately reused before and after capture, so this
proves repeatable restore of request-independent model state across two
accepted random seeds, not unseen receptor or ligand generalization. Earlier
harness attempts failed before qualification because the host validator was
imported from a shallow temporary directory, because the first paired launcher
did not preserve the image's Python path, and because some trial manifests
pointed at the wrong donor bundle or pinned node. Those attempts are retained
as negative evidence and excluded from statistics; no model limits, precision,
steps or validators were relaxed. All six matched trial Pods, the donor and the
publication Pod were deleted after evidence capture. The read-only bundle
remains on the existing regional shared filesystem.
