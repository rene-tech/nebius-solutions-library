# OpenFold / public BioNeMo Inference Runtime evaluation

Core GPU benchmark complete: 312/312 valid inference outputs, with failed
starts retained separately. No production promotion. Fresh evidence dated
2026-09-15. Independent OpenFold3 snapshot qualification is complete with
a negative application result; see `../snapshot/openfold3/result.json`.

**Updated decision: HOLD the OpenFold3 graph/resident serving prototype.**
The subsequent snapshot lane's matched normal-load controls pass warmup
but fail on a repeated identical request key with CUDA illegal memory access.
The core timing matrix used distinct query IDs and recaptured graphs.
Its measured gains remain valid for that restricted workload, but do not
qualify reusable graph serving. The same error in ordinary workers prevents
attributing the failure to checkpoint restoration alone. No cache-reset,
invalidation or alternative runtime variant was implemented or measured.

## Fixtures and measurement boundary

Public monomers 1CRN/46 aa, 1LYZ/129 aa, 1AKE/214 aa; Preview2 additionally
4HHB protein chains A+B/287 aa and T1031/95 aa with its full public A3M.
Sequences, original structures, input and MSA hashes/provenance are under
`fixtures/`. No MSA is silently replaced: OF2's current boundary cannot
accept one; Preview2 receives the complete 267371-byte alignment and its
native MSA cap. No templates are accepted by either current HTTP wrapper.

One first-shape request, three warm repetitions per case, plus three
simultaneous different-shape HTTP requests. Both native adapters serialize
inference under a lock: the latter is a measured queue workload, **not
tensor batching**. No p95/p99/SLO inference from three repetitions.
All individual timings and failures are retained. `measurements.json`
is generated by `aggregate.py`; `quality.json` by `score_outputs.py`.

Clock: in-pod accepted HTTP to complete response, artifact write and basic
validation. OF2 validates sequence, PAE/PLDDT finiteness; OF3 validates CIF
and native confidence fields inline. Offline every successful output is
also checked for exact chain sequence and finite coordinates and scored
against references and the same-GPU baseline. That offline scoring is not
included in request latency. Gateway/network ingress, scheduler and image
pull are outside the request clock, reported separately. Native
`inference_seconds` includes preprocess/forward/confidence/artifact work;
it is **not** a GPU-kernel timer. Fine-grained phase times unavailable from
the exact native worker are null/unmeasured, not invented from totals.

## Results

Warm medians, seconds; n=3 each, exact individual values in measurements.

| L40S OF2 variant | 46 aa | 129 aa | 214 aa | Three-request queue total |
| --- | ---: | ---: | ---: | ---: |
| Exact current | 1.707 | 6.176 | 13.185 | 21.395 |
| Upstream in BIR environment | 1.718 | 6.171 | 13.210 | 21.423 |
| BIR FP32 | 4.844 | 15.496 | 29.392 | 49.675 |
| BIR mixed | 1.188 | 1.493 | 2.408 | 5.084 |

BIR FP32 is slower on these shapes. Mixed precision gives latency ratios
of approximately 1.44x/4.14x/5.47x, explicitly a precision-changing variant,
not a same-FP32 speedup. Unchanged upstream in the newer environment has
essentially unchanged latency. No residency improvement is attributed to
BIR because the baseline is already persistent.

OF2 mixed versus baseline CA-lDDT is 0.9843/0.9677/0.9815; aligned CA RMSD
0.352/0.729/0.752 Å. FP32 CA-lDDT is 1.0000/0.99925/1.0000. These tiny
single-sequence examples have low reference accuracy and confidence in
both implementations. They support a **conditional optimization
prototype**, not scientific-equivalence or broad accuracy certification.

Preview2 H100 exact baseline: 23/23 successful outputs. First accepted
46-aa request took 418.07 s, including native CUDA attention compilation;
warm medians were 8.820/9.448/9.958 s for 46/129/214 aa, 11.140 s for the
287-aa complex and 9.411 s with full T1031 MSA. Three-request queue took
29.454 s. T1031 CA-lDDT against the supplied reference was about 0.850,
CA RMSD about 1.84 Å. The initial BIR r5 full sweep also passed 23/23;
T1031 reference CA-lDDT was 0.8492, paired CA-lDDT 0.9704 / RMSD 0.752 Å.
However r5 restarted a private diffusion seed-42 stream after native
preprocessing while the original consumes the advanced global stream.
Its no-MSA paired structures differ substantially. This is retained as an
exploratory noise-stream variant, not a primary matched-noise speedup.
The corrected adapter uses `sampling_seed=None`: the shipped BIR sampling
context clones/commits the current global state, retaining native
Lightning's seed 42. The primary FP32 H100 sweep passed 23/23. Warm paired
CA-lDDT was 1.0000/0.99167/1.0000 for the three monomers, 1.0000 for the
complex and 1.0000 for full-MSA T1031; corresponding CA RMSD was
0.054/0.391/0.070/0.074/0.048 Å. This supports close agreement on these
examples, not broad scientific equivalence.

Primary Preview2 FP32 H100 warm medians were 8.664/9.174/9.968/11.437/9.160
seconds (46/129/214/287-complex/95-full-MSA), versus
8.820/9.448/9.958/11.140/9.411 current. There is **no meaningful broad warm
latency gain** in this graph-disabled native-lifecycle FP32 prototype. First request was
13.770 s versus 418.074 s in the native cold-compiler cohort. This is not a
30x warm speedup, nor a fully baked-image startup comparison: images,
initialization and prototype dependency installation are separate phases.
Persisting/prebuilding native compiler caches is another potential cold
startup remedy, not measured here.

OF2 H100 warm medians for current / BIR FP32 / BIR mixed were
0.984/1.516/0.927 s (46 aa), 2.275/4.352/1.035 s (129 aa), and
4.292/7.897/1.213 s (214 aa). Thus FP32 is slower on both GPUs; mixed
precision is conditional on quality, with stronger gains on larger shapes.

OF3 mixed H100 medians were 8.171/8.754/9.106/9.659/8.682 s; L40S
10.408/10.769/11.251/11.788/10.699 s. Despite valid outputs, paired
H100 CA-lDDT for 46/214-aa examples dropped to 0.835/0.559 (RMSD
1.50/10.01 A); full-MSA T1031 remained close. **Hold this mixed-precision
variant**, rather than accept it based only on timing and successful HTTP.

### Eligible CUDA Graph and lifecycle experiment

A bounded `ResidentGPU` inner-model wrapper prevents Lightning's CPU
teardown transfer, retaining CUDA addresses for graph use. The identical
wrapper is applied to the exact upstream model in a same-H100 control;
no native preprocessing, seed, confidence scorer or writer is replaced.
The BIR variant explicitly optimizes `diffusion_module`. Actual tracker
state is `GRAPH_VERIFIED`, with graph objects present and no eager fallback.
Request metadata, including query IDs, enters the graph key, so distinct
requests recapture; that overhead is included rather than removed from
the timings. Multiple real shapes are exercised.

L40S FP32 graph+resident completed 23/23 requests. Warm medians for
46/129/214/287-complex/95-full-MSA were 2.530/3.299/5.932/10.550/3.155 s,
versus current L40S 10.868/11.223/11.706/13.588/11.156 s. These are
combined implementation+graph+residency comparisons, not graph-only ratios.
Monomer/MSA paired CA-lDDT is 1.000, RMSD 0.028–0.112 A. The complex
paired CA-lDDT is 0.896/RMSD 7.49 A and reference CA-lDDT 0.749 versus
native L40S 0.756–0.761; native H100 also showed an alternate complex pose
with reference CA-lDDT 0.749. This is not certified complex equivalence.
The same-H100 resident control and graph candidate each completed 23/23:

| H100 native-boundary variant | 46 aa | 129 aa | 214 aa | Complex287 | Full-MSA95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Exact current | 8.820 | 9.448 | 9.958 | 11.140 | 9.411 |
| Exact upstream + matched residency | 7.658 | 8.535 | 9.315 | 10.356 | 8.648 |
| BIR FP32 graph + residency | 2.291 | 2.983 | 3.972 | 5.674 | 2.838 |
| Resident upstream / graph candidate ratio | 3.34x | 2.86x | 2.35x | 1.83x | 3.05x |

The last row removes the saved teardown transfers from the claimed BIR
gain. It still compares the disclosed native versus BIR software stacks,
not an isolated GPU-kernel microbenchmark. Current / graph candidate
ratios are 3.85x/3.17x/2.51x/1.96x/3.32x and explicitly include residency.
Three-request queues were 29.454 s current, 26.322 s resident-native and
9.327 s graph-BIR. H100 graph first accepted request was 6.070 s versus
419.030 s for resident-native cold compilation; image/init/load clocks
remain separate, so this is not a fully baked deployment startup ratio.

Paired H100 graph-versus-resident-native CA-lDDT is 1.000 for every warm
case; RMSD is 0.064/0.138/0.082/0.049/0.020 A respectively. Against exact
current H100, CA-lDDT is 1.000/0.99167/1.000/1.000/1.000. This supports a
**performance potential in the FP32 graph/resident prototype**, not
deployment or broad scientific equivalence. The later repeated-key failure
now places graph serving on hold. Keep the mixed variant on hold as well,
and qualify the L40S complex pose difference before widening scope.

## Features and failure accounting

Actual native and candidate negative HTTP probes are retained in
`raw/*/feature-probes.json`: 80 deliberate invalid-feature probes returned
the expected400, separate from312 valid inference requests.
OF2 rejects MSA, templates, seed changes,
other parameter sets, relaxation and a batch object (400). Preview2 rejects
templates, ligand/RNA/DNA, seed override, multiple samples and multiple
inputs (400). Preview2 monomer/protein-complex/full-MSA paths are real
positive benchmarks. Unsupported current-wrapper features are not BIR
regressions; this evaluation does not claim BIR fixes them.

No cancellation/idempotency contract is advertised by these native
adapters; disconnect/retry behavior and the production MCP gateway are not
qualified here. One successful repeated-input response is not an
idempotency guarantee. PDB/PAE/native confidence remain OF2 outputs;
Preview2 returns CIF and native ranking/PLDDT/PDE/PTM/IPTM fields.

Preserved startup failures: initial BIR base lacked a C compiler for
Triton's driver binding; first OF3 overlay attempted to uninstall a
read-only global SciPy; a subsequent nonroot Torch cache lookup lacked a
username; OF3's default cache then resolved to unwritable `/.openfold3`.
The corrected recipe uses a compiler, an isolated pinned overlay and
explicit writable task-local cache paths. These failures consume reserved
GPU time and remain in the aggregate; they are not erased as warmups.

## Cost, cold state and snapshots

`measurements.json` reports whole-study allocated GPU seconds and
successful requests per allocated GPU-hour, including initialization,
failed starts, operator delay and termination. Early resources have a
lower bound from collection and an upper bound from the next exclusive
GPU pod; later resources have explicit deletion-request/observed receipts.
These research-run totals are not production steady-state economics.
The20 resources consumed6888.8–7513.9 allocated GPU-seconds total
(1.914–2.087 GPU-hours), including four failed starts and all collection/
operator/termination time:22.08–24.08 seconds per artifact-valid request.
Pure GPU busy time, process CPU time and monetary cost are unmeasured.
No unverified cloud rate is applied.

Image pulls, fresh process readiness, first-shape compilation and warm
worker requests are distinct. No shared cache was flushed. BIR init-pod
asset copying and prototype dependency installation are included in cold
allocation but are not a production-baked-image startup forecast.

CUDA Graph is not CUDA process snapshot. Public OF2's optimization
registry contains no graph module; these runs have no CUDA Graph capture.
OF3 defaults also do not enable graph capture; the explicit graph/resident
variant above is measured separately. Fresh-pod qualification in
`../snapshot/openfold3/` deleted the donor before all three successful
low-level CUDA+CRIU restores, but all restored inference schedules failed.
All three ordinary-load controls also failed when reusing their warmed
query key, so restoration is not an isolated cause. Median readiness was
292.779 s restored versus 65.349 s normal; no valid-result startup benefit
or restored-output parity is established. The identity-mismatch fallback
served three distinct keys, not repeated-key reuse. Same physical H100 and
driver only; cross-node portability is untested. Independent OF2 fresh-pod tests
passed but were slower than their matched normal starts (see sibling
snapshot report). No historical native Preview2 snapshot measurement is
relabeled as fresh BIR evidence.
